## Installation

1. Make a local copy/clone of this repo.
2. Make a fresh Python virtual environment, version 3.11.15, and enter this virtual environment for remainder of all following steps.
3. Install required modules - versioning is important. See requirements.txt for a `pip freeze` of the packages installed on the Python venv with which we generated our results.
5. Inside the repo root directory (i.e. the directory within which we can access 'hpvsim', 'project_documents', 'project_modelling', etc), run `pip install -e .`. This installs our version of HPVsim into the repo, in editable mode (such that any changes you subsequently make within the 'hpvsim' directory are reflected when you run HPVsim, automatically).
6. Run the following
```
python
import hpvsim as hpv
```
  You should observe the output `Loading HPVsim adapted for England Cervical Screening Project.`. If this appears, installation is successful. If not, consult previous steps.

## Result Replication

This repo allows for direct replication of our modelling results as well as exploration of alternative scenarios. Explore a scenario with the following steps:
1. FIX NON-CAL PARAMETERS: .csv files within `hpvsim/data/` determine characteristics of all interventions other than the 'General Cancer Treatment' intervention (e.g. to change colposcopy specificity, look here). Change these as necessary for the scenario being considered.
2. FIX NON-CAL PARAMETERS: `project_modelling/InterventionAlgorithms/GlobalScreeningParameters.py` defines characteristics of the 'General Cancer Treatment' intervention, compliance parameters, and some basic parameters pertaining to screening algorithgms (when screening is to start, the year at which we switch from the default screening algorithm to a candidate alterantive algorithm, and how long to follow-up individuals who have not accepted a screening invititation). e.g. projected vaccine uptake is set in this file
3: FIX NON-CAL PARAMETERS: `project_modelling/basePars.py` defines all other parameters that do not pertain to screening algorithms (in particular, population level parameters such as initial HPV prevalence and mixing matrices)
4: FIX NON-CAL PARAMETERS: `project_modelling/scenario_configuration.py` defines the specific screening algorithm being switched to and the name of that algorithm (change this by defining your own intervetnions, or making use of the interventions defined in `project_modelling/InterventionAlgorithms/NHS_2025_lambdamu.py`, `project_modelling/InterventionAlgorithms/NHS_2025_lambdamuForVaccCohortsOnly.py`, and `project_modelling/InterventionAlgorithms/NHS_Vacc.py`). 
5: ENSURE CORRECTNESS OF SCENARIO ENCODING: `project_modelling/scenario_configuration.py` also defines a suffix for calibration-files and result-files according to the parameterisation of the scenario that gave rise to these files. If you have changed any parameters in steps 1-3 that are not included already (or are performing a fine-grained sensitivty analysis which sees parameters varied at a resultion not captured by their most significant figure), you will need to change this encoding.
6: PREPARE CALIBRATIONS: `project_modelling/calibrationScript.py` defines the calibration of our model to the selected parameters. Define the parameters you wish to calibrate and the data file(s) to which you wish to calibrate (if different to the current selection of parameters and current data files). If you wish to change the interventions modelled in this calibration, that needs to be changed here too (as well as reflected in scenario modelling).
7: PERFORM CALIBRATIONS: Run `project_modelling/calibrationScript.py` to complete a calibration. The calibration will be saved into `project_modelling/calibration_results/`. Each time you run the calibration, you will need to specify a new name for it (a useful naming convention is 'DATE_{n}' where n is incremented according to how many calibrations you have performed so far that day). The name will have a suffix determined by the parameters you have determined in steps 1-3 (as described in step 5). Complete at least 3 full calibrations (i.e. c. 5k trials x3).
8: CHECK AND COMPILE CALIBRATIONS: Your several calibrations as generated in the previous step must be unified into a single set of the most feasible model parameterisations. The script `project_modelling/calibrationProcessing.ipynb` uses Optuna Dashboard to visualise and interact with calibrations, to check your calibrations for convergence, good coverage of parameter space, etc. Note that for large number of trials, contour plots are prohibitively costly.Redo step 7 if needed to make new calibrations (e.g. with larger ranges for calibrated parameters if it seems necessary). Continuing working through this script, next combine these calibrations into a single calibration by loading them all in, filtering for the best x% of calibrations, and filtering for similarity. Then save the final calibration using the name according to that generated by `project_modelling/scenario_configuration.py` (`cal_filename`), to a pickle file which can be loaded when generating results subsequently.
9: GENERATE RAW RESULTS FOR THIS SCENARIO: Run `project_modelling/run_model.py` to generate a set of raw results for the scenario we have set up in steps 1-4 and using the calibrated parameters from steps 7 and 8. 
10: GENERATE RESULTS FOR RELATED SCENARIOS: We will want to compare the results generated in step 9 against results generated from other scenarios. If scenarios A and B do not differ in terms of parmaeters defined in steps 1 and 3, differ in step 2 by at most `projected_teen_vaccination_uptake`, and differ in step 4 by at most the interventions that occur at/after 2026* (or the latest date for which we have data to calibrate, whichever is later), then we do not need to re-calibrate our model for these two scenarios (as all parameters that affect historical data to which we calibrate are unchanged). We should not recalibrate the model therefore, to allow for paired t-tests between outcomes in the two scenarios. Generate results from these alternative scenarios by changing `project_modelling/InterventionAlgorithms/GlobalScreeningParameters.py` and  `project_modelling/scenario_configuration.py` as required, and immediately repeating step 9 (i.e. consider cases where there are different levels of vaccine uptake and different screening interventions post-2026*). Note that if scenario encodings defined in  `project_modelling/scenario_configuration.py` are changed (which would have occured in Step 5), then the encoding must be defined such that any alternate, 'related', scenarios considered in this step yield the correct calibration file (which should be the same file used for generating results in Step 9, and the same file genearted in Step 8).
11: GENERATE POLISHED RESULTS: `project_modelling/resultGeneration.py` provides a suite of functions to yield 'polished results' comparing model outputs for related scenarios using paired t tests, and otherwise outputting comparisons of scenarios. These functions generally require specifying one or many 'algorithms' to generate results over (these are the same as scenarios, and are specified by their `alg_name` as defined in `project_modelling/scenario_configuration.py`), and the 'quantity' we are interested in (e.g. all cancer incidence, incidence of cancer which is attributable to vaccine-type HPV within the vaccinated subpopulation, etc), whether to normalise values per 100k, and potentially the start and end timepoints within the simulation we are interested in (the mapping between timepoints and simulation-time in years is determined by `project_modelling/basePars.py`; by default, it is TIMEPOINT=4*(YEAR-1980)). Note that if your set of algorithms/scenarios includes those generated with different final calibrations (e.g. because they assume different levels of cytology sensitivity), it is not appropriate to do any 'paired' analyses.


*2026 may not be the year in which screening algorithms switch between the base algoruthm and alternately considered case: if `project_modelling/InterventionAlgorithms/GlobalScreeningParameters.py.switch_year` is changed then replace '2026' with whatever value this variable is.


## Disclaimer

This code allows replication of modelling results from a research project into Cervical Screening in England, using the HPVsim model as developed by the Institute of Disease Modelling (IDM), the Burnet Institute, and other collaborators. Its underlying model is HPVsim 2.2.4, with adaptations to align with modelling needs in England. See https://github.com/StarSimHub/HPVSim for the latest version of the base model.
